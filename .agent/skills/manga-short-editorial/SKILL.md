# 漫画紹介ショート動画（エディトリアル版）作成・量産ガイド

本スキルは、プロジェクト「0001」「0002」で確立された**漫画紹介ショート動画（1080×1920 縦型・全13シーン・約58秒）**の構成テンプレート、デザインシステム、Remotionコンポーネント実装規則、およびWebワークスペース連携仕様をまとめたものです。
他の漫画作品でも本ガイドラインに従うことで、まったく同一のクオリティ・アニメーション・テンポ感を持った動画を極めて迅速に量産できます。

## 1. 動画全体の基本仕様 (Video Specs)

- **解像度**: `1080 × 1920`（アスペクト比 9:16 / 縦型ショート）
- **フレームレート**: `30 fps`
- **総尺**: **約58秒（全 1700〜1750 フレーム）**（YouTube Shortsの60秒上限を確実に下回る安全設計）
- **BGM**: **基本的に入れない**（セリフ音声＋効果音SEのみですっきりと聞き取りやすくする）
- **音声スピード**: 自然でテンポの良い **1.08倍速**（ピッチ維持タイムストレッチ）
  - 各セリフ末尾に約0.2秒（6フレーム）の呼吸（間）を自動付加
- **話者体系（VOICEVOX 3話者）**:
  - 🌸 **女性キャラ**: 春日部つむぎ（VOICEVOX ID: 8 / `[pink:...]` マゼンタピンク吹き出し）
  - 👓 **男性キャラ**: 玄野武宏（VOICEVOX ID: 11 / `[blue:...]` ブルー吹き出し）
  - 🎙️ **ナレーション**: 青山龍星（VOICEVOX ID: 13 / `[red:...]` 赤強調または黒立体文字）
- **セリフのボイス読み上げ原則（核心仕様）**:
  - **シーン01（冒頭フック）**: 上部タイトル（固定フック）は読み上げず、**下部テキストの内容（先行リード文＋着弾パンチライン）をナレーション（青山龍星）で読み上げます**。
  - **最後のシーン（CTA）**: 基本的には**上部テキスト（作品詳細への誘導テキスト）をナレーション（青山龍星）で読み上げます**（下部の「3点リーダーやタイトルから」等は視覚的案内テロップとして扱い、読み上げません）。
  - **それ以外のシーン（シーン02〜最終シーン手前）**: **画面内のテキスト（各コマの画面テキスト）を、指定されている 女性（🌸 春日部つむぎ） または 男性（👓 玄野武宏） または ナレーション（🎙️ 青山龍星） で読み上げます**。
- **背景テーマ**:
  - `theme: 'manga-page'`（通常シーン: 白〜薄アイボリー原稿風背景＋外枠フレーム＋`MANGA SHOKAI // P.XX` スタンプ＋四隅トンボ＋アミ点トーン）
  - `theme: 'manga-dark'`（クライマックス・ラストシーン: 黒背景＋白文字＋ダーク集中線）
  - `fallingMangaBg: true`: 背景で3D漫画単行本・原稿ページが連続して上から下へ立体的に流れる演出（`useGlobalFrame()` 駆動）
- **中央漫画コマ枠仕様**:
  - **コマ内枠サイズ**: 縦 **`800px`**（全シーン統一で枠のガタつきを防止）
  - **コマ画像の最大高さ**: **`820px`**（`objectFit: 'contain'` で絵や吹き出しの欠けをゼロにしつつ縦いっぱいにフィット）
  - **コマ外枠**: 外枠パディング `10px`、黒枠 `5px`、ソリッド影 `12px` でエディトリアルな重厚感を演出

## 2. シーン01（冒頭フック特大演出・全作品固定仕様）

動画の冒頭で視聴者の離脱を防ぎ、視聴維持率を跳ね上げる専用のフック構成です。

1. **上部固定見出し（全作品共通・編集不可）**:
   - 以下の2行構成で完全固定（各行とも途中折り返しなし）：
     ```text
     1行目: 大人の[red:99%]が読んでいる   （全13文字 / 約64px）
     2行目: [pink:ムフフ]な江戸漫画        （全8文字 / 約94px）
     ```
   - 定義定数: `DEFAULT_MANGA_SCENE01_TITLE = '大人の[red:99%]が読んでいる\n[pink:ムフフ]な江戸漫画'`
   - レンダラー側で `whiteSpace: 'nowrap'`, `flexWrap: 'nowrap'`, `wordBreak: 'keep-all'` を適用し、画面幅820px内に1行ずつスマートに収まるよう自動サイジング。
2. **コマ画像（コマ1）演出**:
   - 0〜14フレーム: 覗き込む目元へ **`2.45倍` 超ドアップ**
   - 15フレーム目〜: 全体像（`1.10倍`）へ **急ズームアウト** ＋ **薄オレンジ集中線（`#ffa059`）** ＋ 右上特大 **『!?』** ＋ 白/赤インパクトフラッシュ
3. **コマ下部リード文**:
   - コマの直下に表示される導入文（例: `[blue:衝撃の光景]を目の当たり\nにしてしまった主人公が` / 76px）
4. **着弾パンチライン（footerHeadline）**:
   - 冒頭フックの結論コピー（例: `[red:ヤバすぎた]` / 特大 **`164px`**）
   - 急ズームアウトと同時に画面上へ激しくスタンプ着弾
5. **効果音（SE）同期**:
   - 3フレーム目: `驚く.mp3`
   - 着弾タイミング: `小パンチ.mp3` ＋ `和太鼓でドドン.mp3` ＋ 画面カメラシェイク（12フレーム減衰）

## 3. シーン02以降：コマ単位（コマ1 / コマ2 / ... / コマN）独立モデル

1つのシーン内で、ダイアログや状況の進展に合わせてコマやテキストをスムーズに切り替える統合アーキテクチャです。

### A. コマ単位カードの基本構造
各シーンは複数のコマ（`panels: MangaPanelSpec[]`）を持ち、コマごとに以下の要素を独立管理します：
- 🖼️ **コマ画像 (PNG)**: 表示する画像URL（例: `/manga/0002/panel_02.png`）
- 📝 **画面テキスト**: 改行を含めて入力可能（行の文字数に応じた自動フィット）
- ↕️ **テキスト配置**: `top`（上部見出し・吹き出し）または `bottom`（下部ナレーション・吹き出し）
- 🎭 **セリフ・話者**: 女性 🌸 / 男性 👓 / ナレーション 🎙️（インライン装飾タグ自動付与）
- ⏱️ **表示フレーム数**: そのコマが表示される尺（30fps換算、1.08倍速テンポ自動計算）
- 🔊 **音声URL / 効果音SE**: VOICEVOX音声パスおよび、各コマごとに適用される「テキスト出現・コマ切り替え効果音 (SE)」ドロップダウン

### B. コマごとの効果音（SE）設定仕様
- 各コマ（コマ1、コマ2、...コマN）の設定項目内に「🔊 テキスト出現・コマ切り替え効果音 (SE)」を個別に配置。
- 各コマが表示される（テキストが出現・切り替わる）フレームタイミングに合わせて、設定されたSEが正確に発火。
- シーン全体の設定欄には「シーン切り替え効果音（トランジションSE）」のみを置き、コマ単位のSEと明確に分離。

### C. 画像の継続表示 ＆ アニメーション抑制ルール（核心仕様）
- **コマ1に画像があり、コマ2以降で画像が未設定（空欄）の場合**:
  - **コマ切り替えアニメーション（バウンド・ジャンプ、枠の傾き変更、背後の重なり枠）は一切発生しない**。
  - コマ1で設定された画像がそのまま静止した状態で出続ける。
  - コマ1のテキストはフェードアウト・消去され、**コマ2で設定されたテキストのみが指定位置（上部/下部）に排他的に表示される**。
- **新しい画像が明示的に設定されたコマに到達した場合**:
  - コマ切り替えアニメーション（バウンド・重なり枠・角度変更）が発動し、新画像に切り替わる。

### C. スロット単位（上部／下部）の持続表示 ＆ 上書き更新ルール
- **配置が異なる場合（例: コマ1が上部、コマ2が下部）**:
  - コマ1の上部テキストは、コマ2になってもそのまま上部に表示され続け、下部にコマ2のテキストが追加表示されます（シーン07等の標準対話・ナレーション展開）。
- **配置が被った場合（上部→上部、または下部→下部）**:
  - コマ2の開始フレームに達した瞬間に、**同一スロットの前のコマのテキストは消去され、次のコマのテキストに綺麗に上書き更新**されます（重なって残ることはありません）。
- **話者カラー ＆ 吹き出しの独立保証**:
  - 配置の組み合わせに関わらず、それぞれのコマの話者設定（女性 🌸 / 男性 👓 / ナレーション 🎙️）に応じたインライン装飾タグが独立して適用されます。
  - 女性ならピンク楕円吹き出し、男性ならブルー楕円吹き出しがそれぞれ確実に表示され、ナレーション化してしまう不具合を防止します。
- **コマ・テキスト位置の不動キープ（レイアウトシフト防止＆全シーン高さ統一仕様）**:
  - 後から下部テキスト（または上部テキスト）が出現するシーンでも、出現予定のテキスト領域を最初から不可視プレースホルダー（`visibility: hidden`）として確保。
  - 下部テキストが途中で出現した際に上部テキストや中央のコマ画像が上に持ち上がるようなガタつき（レイアウトシフト）をゼロにし、最終的に上部と下部のテキスト・コマが入った状態の安定した位置を最初から最後まで完全にキープします。
  - **上部テキストのみのシーン（シーン04、シーン06、シーン08、シーン09など）における他シーンとの高さ完全統一**:
    - 下部テキストエリアに標準ナレーション・セリフ基準の `minHeight: 190px` プレースホルダー空間を確保。
    - これにより、下部テキストが配置されていないシーンでも下部テキストが存在する他シーン（シーン02、03、05、07など）と全体のコンテンツ高が寸分違わず一致し、中央の漫画コマ枠および上部テキストの画面Y座標が全シーンでミリ単位でピタッと同一の高さに揃います。シーン切り替え時にコマが上下に沈んだり浮いたりする違和感を根本的に解消しています。

## 4. テキスト装飾記法（インラインタグ）と吹き出しシステム

`KineticRichText` および `EditorialBackdrop` で自動解析・描画される記法です：

- **`[pink:テキスト]`**: 女性キャラクターのセリフ（マゼンタピンク `#f01c74`）
  - 行全体が `[pink:...]` の場合、自動的に**背後に白塗り＋黒枠＋アミ点影の楕円形コミック吹き出し**が付着。
- **`[blue:テキスト]`**: 男性キャラクターのセリフ（ブルー `#2262dc`）
  - 行全体が `[blue:...]` の場合、自動的に**背後に白塗り＋黒枠＋アミ点影の楕円形コミック吹き出し**が付着。
- **吹き出しの向きとしっぽの先端方向**:
  - **上部配置時**: しっぽの先端は**下向き**（コマの中央方向）を指します。
  - **下部配置時**: 吹き出しSVGが自動的に**上下反転**し、しっぽの先端が**上向き（コマの中央方向）**を指すよう描画されます（光源と影の方向は美しく維持され、文字パディングも上下対称に追従）。
- **コマ位置の完全固定と吹き出しクリアランス（コマ被り防止）**:
  - 上部・下部のセリフ吹き出し（しっぽを含む）が中央の漫画コマ枠に被らないよう、コマ枠との間に安全なクリアランス（約20〜30px）を確保。
  - 上部見出しラッパーに標準ナレーション基準の `minHeight: 190px` および `justifyContent: center` を適用することで、上部テキストが1行/2行、セリフ/ナレーションを問わず、中央の漫画コマ枠の画面Y座標を「上部ナレーション基準」の定位置に完全固定。どのセリフが入ってもコマが上下にズレず、かつ吹き出しがコマに重ならず程よい距離感で美しくレイアウトされます。
- **`[red:テキスト]`**: 最大強調キーワード（レッド `#dc1e28`、白フチ＋立体押し出し影）
- **タグなし**: ナレーション・地の文（視認性の高いブラック `#181818`、白フチ＋立体押し出し影）
- **フォントサイズ基準**:
  - シーン01着弾パンチライン: **`120〜164px`**（画面下部にドカンと着弾する特大結論フック。文字数に応じて画面幅いっぱいに自動スケーリング）
  - シーン01先行リード文: **`52〜54px`**（パンチラインを引き立てる控えめで読みやすい小さめサイズ）
  - 楕円セリフ吹き出し: **`58〜64px`**（横幅の60〜70%に程よく収まる上品なサイズ）
  - 通常上部見出し: **`56〜68px`**
  - 通常下部ナレーション: **`50〜56px`**
  - ※ テキスト表示幅は、漫画コマの幅（約980px）より少し狭い **`800〜840px`** に収まるよう動的サイジングされ、幅を超える場合は指定された改行箇所で折り返します。

## 6. Webワークスペース（UI）とチャット作成プロトコル

方針ファイル（`漫画紹介動画テンプレート方針 - 方針.csv`）に完全準拠した制作環境です。

### A. ワークスペース（Web画面左側）の機能
1. **シーン01〜最終シーンの横スクロールナビゲーション**: ワンクリックで各シーンを選択・即座にプレビュー。
2. **シーン01の固定フック表示**: 上部タイトルはロック表示され、コマ画像と下部テキスト・着弾パンチラインのみを設定。
3. **コマ単位（コマ1 / コマ2 / ... / コマN）での編集**:
   - 各コマの画像PNG指定（パス入力 or ファイルピッカー即時反映）。
   - コマ2以降で画像が空欄の場合は「コマ1の画像を継続表示（アニメーションなし）」と自動ガイド。
   - 画面テキストの入力、改行反映、上部/下部配置セレクタ、話者切り替え（🌸女性/👓男性/🎙️ナレーション）。※画面テキストと音声セリフは自動同期され、余計な二重入力を排除。
   - コマごとの効果音（SE）ドロップダウン設定（各コマの開始タイミングで指定SEを自動再生）。
   - 「＋ 新しいコマを追加 (コマN)」ボタンによる動的コマ追加、コマ削除。
4. **効果音（SE）＆背景演出設定**:
   - コマ単位SEに加え、シーン全体の切り替えSE設定。
   - 「📚 背景で漫画単行本・原稿を流す演出（`fallingMangaBg`）」は全シーン標準でチェックボックスがデフォルトON。
5. **データの永続化（自動保存＆JSONバックアップ）**:
   - ワークスペースで行った全設定（画像・テキスト・コマ・SE・演出等）はブラウザの `localStorage` に常時リアルタイム自動保存。
   - ページのリロードやチャット内でのコード編集時にも変更データが失われず、直前に開いていたプロジェクト画面がそのまま復元されます。
   - ツールバーの「📥 JSON保存」「📤 JSON読込」ボタンから、設定データ全体のPCローカルへのバックアップ保存および復元が可能。
6. **「✨ テンプレート演出で動画を綺麗にする」ボタン**: 黄金律を一発で自動適用。

### B. チャット連携プロトコル
- ユーザーから「**綺麗にして**」「**ブラッシュアップして**」とチャットで指示された場合：
  1. シーン01の上部固定タイトル（2行折り返しなし）を保証。
  2. 各シーンのダイアログから話者を自動判定し、`[pink:...]`, `[blue:...]`, `[red:...]` タグを最適配置。
  3. テキストの1行が10〜14文字程度になるよう自然な改行を調整。
  4. トランジション（スラッシュ、ブラインド、パネルワイプ）をバランス良く配置。
  5. コマ2で画像未設定の場合はアニメーション抑制＆テキスト排他切り替えを適用。

## 7. 他の漫画作品を量産する手順

### 方法 A: CLIスクリプトによる一発全自動生成（最速・推奨）

台本JSONを用意してスクリプトを1回実行するだけで、**VOICEVOX音声合成 → 1.08倍速タイムストレッチ → 尺計算 → VideoSpecコード生成**まで全自動で完了します。

#### Step 1. コマ画像の切り抜きと配置
```bash
frontend/public/manga/<作品ID>/
├── panel_01.png   # シーン01用（フック・目元寄り）
├── panel_02.png   # シーン02用
├── panel_03.png
├── ...
└── panel_11.png   # シーン11用（クライマックス）
```

#### Step 2. 台本JSONの作成
`scripts/templates/manga_script_template.json` をコピーして編集：
```json
{
  "projectId": "0002_my_manga",
  "title": "作品タイトル",
  "atempo": 1.08,
  "scenes": [
    {
      "scene": 1,
      "mediaUrl": "/manga/0002_my_manga/panel_01.png",
      "title": "大人の[red:99%]が読んでいる\n[pink:ムフフ]な江戸漫画",
      "footerLead": "[blue:衝撃の光景]を目の当たり\nにしてしまった主人公が",
      "footerHeadline": "[red:ヤバすぎた]",
      "focusLines": true,
      "dialogues": [
        { "speaker": "narration", "text": "衝撃の光景を目の当たりにしてしまった主人公が……ヤバすぎた" }
      ]
    }
  ]
}
```

#### Step 3. 自動生成スクリプトの実行
```bash
python scripts/create_manga_shorts.py path/to/my_manga_script.json
```
- VOICEVOX（ポート50021）でWAVファイルを一括生成し、`atempo=1.08` で高速化。
- ダイアログ実尺からフレーム数を精密計算し、`frontend/src/types/generated/<作品ID>.ts` に VideoSpec を自動出力。

#### Step 4. プレビュー & レンダリング
```bash
# Web UIで確認
npm --prefix frontend run dev

# ユーザーから指示があった場合にのみMP4レンダリングを実行
npm --prefix frontend run build
npx remotion render src/remotion/index.ts MainVideoShorts output/<作品ID>.mp4 --props='{"specId": "<作品ID>"}'
```
